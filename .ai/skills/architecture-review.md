# Skill: Architecture Review

Use when:
- adding/removing a component;
- changing ownership boundaries;
- changing persistence;
- changing public contracts;
- changing trust boundaries;
- adding major dependencies.

Check:
1. architectural invariants;
2. responsibility ownership;
3. coupling;
4. public contracts;
5. data ownership;
6. trust boundaries;
7. migration;
8. rollback;
9. ADR requirement;
10. verification coverage.

Output:
- PASS
- PASS_WITH_CONCERNS
- ARCHITECTURE_CHANGE_REQUIRED
- REJECT
